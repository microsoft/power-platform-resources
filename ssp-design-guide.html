Design/New solution

Launch a new solution

Turn your idea into a clear design, from the first business question to a build-ready blueprint.

Bring to the design session

Your intended outcome, user groups, existing systems, sensitive data, timeline, and measures of success.

Supporting published skills

  • powercat-pp-architecture-advisor - Discovery and architecture review for a composed Power Platform solution.
  • dv-metadata - Dataverse tables, relationships, forms, and views.

Suggested sequence

  1. Frame the problem and solution boundary

    Identify the work to improve and the systems that must remain. Record the scope, assumptions, and constraints in a short solution brief.

    • Microsoft Learn: Create a plan
    • Design guide: Solution Architecture Blueprint

  2. Choose the experience and data model

    Match user tasks to an app experience. Define core entities, relationships, and ownership before selecting components. Keep a model and a record of the alternatives considered.

    • Design guide: Experience Pattern Selector
    • Design guide: Dataverse Data Model Designer
    • Microsoft Learn: Dataverse overview

  3. Set access boundaries and challenge the design

    Map roles to data and actions, then review the proposed architecture. Leave with an access matrix and a prioritized list of risks to resolve before delivery.

    • Design guide: Security Role Mapper
    • Microsoft Learn: Security roles and privileges
    • Assessment: Power Platform Well-Architected
Design/Modernize an app

Modernize an existing app

Keep what works. Rethink what doesn't. Find a lower-risk path from today's app to your next design.

Bring to the design session

The current architecture, user pain points, performance evidence, dependencies, data volumes, release process, and support commitments.

Supporting published skills

  • powercat-pp-architecture-advisor - Compare architecture choices before changing the implementation.
  • migrate-to-dataverse - Relevant when moving a SharePoint-backed canvas app toward Dataverse, not a general-purpose app migration.

Suggested sequence

  1. Assess the current system

    Separate design limitations from implementation issues. Record a baseline and the constraints a replacement or incremental change must satisfy.

    • Microsoft Learn: Well-Architected guidance
    • Design guide: Well-Architected Design Check

  2. Compare target experiences and integration patterns

    Compare retaining, extending, or replacing the current experience. Document data ownership, latency, failure handling, and coexistence requirements alongside the chosen architecture.

    • Design guide: Experience Pattern Selector
    • Design guide: Integration Pattern Selector
    • Microsoft Learn: Architecture Center

  3. Plan a reversible transition

    Define solution boundaries, test environments, migration checks, rollout stages, and rollback criteria. Agree on ownership before changing the production system.

    • Design guide: ALM Topology Planner
    • Microsoft Learn: Application lifecycle management
Design/Enterprise scale

Design for enterprise scale

Give more teams room to build, with clear ownership, secure access, and repeatable delivery.

Bring to the design session

Tenant and compliance constraints, delivery teams, data classifications, environment inventory, support model, and release responsibilities.

Supporting published skills

  • dv-security - Dataverse roles, users, business units, and access.
  • plan-alm - Solution boundaries, pipelines, and deployment topology for Power Pages.

Suggested sequence

  1. Define environment and ownership boundaries

    Group workloads by purpose and risk. Agree who owns each environment, how makers are routed, and where development, testing, and production belong.

    • Design guide: Environment Strategy Blueprint
    • Microsoft Learn: Environment strategy

  2. Set access and data policies

    Map personas to least-privilege access and define connector boundaries. Document policy exceptions, approval owners, and how controls will be reviewed.

    • Design guide: Security Role Mapper
    • Microsoft Learn: Data policies
    • Microsoft Learn: Security overview

  3. Establish delivery and operational controls

    Define pipeline stages, approvals, source control, and support ownership. Produce a delivery topology and a release checklist that teams can repeat.

    • Design guide: ALM Topology Planner
    • Microsoft Learn: Pipelines in Power Platform
    • Resource collection: Governance
Design/Validate a design

Validate a proposed design

Find the gaps before you commit. Turn design risks into clear decisions and next actions.

Bring to the review

The proposed architecture, key decisions, user journeys, security model, service expectations, known risks, and any prototype or test evidence.

Supporting published skills

  • powercat-pp-architecture-advisor - Discovery and architecture review for a proposed solution.
  • security-review - Security-focused assessment when a Power Pages site exists; not a substitute for reviewing an unbuilt design.

Suggested sequence

  1. Assess the design across quality areas

    Review reliability, security, operational excellence, performance efficiency, and experience optimization. Record gaps and their business impact.

    • Assessment: Power Platform Well-Architected
    • Microsoft Learn: Well-Architected guidance
    • Design guide: Well-Architected Design Check

  2. Resolve the material design risks

    Route findings to the relevant architecture, data, or access decision. Capture alternatives, tradeoffs, and acceptance criteria rather than treating a checklist as approval.

    • Design guide: Solution Architecture Blueprint
    • Design guide: Dataverse Data Model Designer
    • Design guide: Security Role Mapper

  3. Agree on evidence and next actions

    Assign an owner to each remaining risk and define what must be demonstrated before release. When an implementation exists, use the Review pillar's tools or request a deeper review.

    • Review tools and deep-review options
    • Resource collection: Architecture guidance
